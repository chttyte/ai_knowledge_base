## 一、`切分测试.md` 每一节在测什么

| 节 | 设计意图 | 预期结果 |
|---|---|---|
| `# 迷你产品手册` + 正文 | 最基本的"一级标题+正文" | 切 1 块，标题和正文都在 |
| `## 简介`（后面只有空行，紧跟 `## 重要提示`）| **光杆标题**：自身没正文 | ⚠ 见第三节，这是你我的差异点 |
| `## 重要提示` + 两行正文 | 确认上一节没被拖累 | 切 1 块，两行正文都在 |
| `### 2.1` + ` ```bash ` 代码块（内含 2 行 `#` 注释）| **`is_code_block` 的核心**：代码里的 `#` 不能当标题 | 代码块完整留在这一块里，`# 查看设备状态` **不能**成为标题 |
| `### 2.2` + `~~~python` 代码块 | 另一种围栏 `~~~` 也要能识别 | 同上，`# 这行也是代码注释` 不能成为标题 |
| `## 3 紧挨着的两个标题` 紧跟 `## 3.1` | **`len(...) > 1` 门槛真正生效的场景** | `## 3` 被丢弃（两个版本都丢），只留 `## 3.1` |
| `####### 七个井号不是标题` | 正则上限是 6 个 `#` | **不是**标题，当正文追加到上一块 |
| `##没空格也不是标题` | `#` 后必须有空格 | **不是**标题，当正文追加 |
| `   ## 缩进标题应该被识别` | `\s*` + 先 `strip()`，缩进不影响 | **是**标题，要切一刀，且 `title` 里不带缩进 |
| 行内代码 `` `# 这个井号在反引号里` `` | 单反引号不是围栏，也不是标题 | 不影响切分 |
| `## 附录`（文件最后一行，光杆）| 收尾是无条件 append | 会留下一个只有 5 个字的准空块 |

## 三、你的版本 vs 教案版：只有 1 处差异，但影响 2 个地方

教案版会切出 **8 块**，多出来的那一块是：

```
[1] '## 简介'  ->  '## 简介\n'          ← 教案版留下的
```

具体差异：

| | 你的版本 | 教案版 |
|---|---|---|
| 块数 | 7 | 8 |
| `## 简介` | 丢弃 | 留成 `'## 简介\n'`（标题+空行，没有正文）|
| content 里的空行 | **全部没有** | 保留（`'...\n\n...\n'`）|

两个后果：

**1. 丢的是真标题。** `## 简介` 不是假标题，它是章节父标题，只是正文都在子标题里。你真实文档里有 12 个这样的（`## 简介`、`## 故障排除`、`## 11 附录`…）。丢了它们，子块就失去了"我在哪一章"的线索。

**2. 空行没了会拖累下一步。** `_split_long_section` 的切分器分隔符优先级第一位是 `"\n\n"`（段落边界），全靠空行判断。你的 content 里一个 `\n\n` 都没有，段落级切分永远用不上，超长块只能退到按 `\n` 或按标点硬切。上面 `[2]` 就能看出来——代码块和正文挤在一起，教案版是分离的。

这块怎么取舍你自己定，但两个后果要先知道。

## 四、`无标题.md`（1 块）

词条：全文没有 `#` 开头的行，`chunk_size` 停在 0，走 default 兜底。

```
[0] 'default'
    content == 原文（一字不差，含全部空行和结尾换行）
```

注意兜底分支用的是**原始的 `md_content`**，不是攒出来的行，所以空行是保留的。这跟有标题的情况不一致，属于教案原版就有的行为。

## 五、`围栏没配对.md`（1 块）

**这是最值得看的一份。** ` ```python ` 打开后没有关闭，`is_code_block` 一直是 `True`，于是后面所有标题全部失效：

```
[0] '# 正常标题'
    '# 正常标题\n正文第一段。\n```python\n# 这个围栏开了以后就没有关\n## 这个标题永远切不出来\n它已经被当成代码块内容了。后面的标题也一样。'
```

`## 这个标题永远切不出来` 老老实实变成了正文。这模拟的是"PDF 解析被截断、围栏丢了一半"的情况——**真发生时不会报错，只会静默少切几块**。

一个实用的自检点：循环结束后打印一下 `is_code_block`，`False` 才正常。你自己写的时候可以加一行日志，或者在函数返回前加个断言。
